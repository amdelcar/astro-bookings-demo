# Agents Instructions

## Product Overview
- AstroBookings is a fictional backend API for rocket launch bookings.
- The service currently exposes health checks and CRUD endpoints for rockets.
- The project is intentionally a training/demo application, not a production service.
- GitHub username: `amdelcar`
- Repository: https://github.com/amdelcar/astro-bookings-demo

## Current Architecture
- The app is built with **TypeScript 5.7** and **Express 5**.
- Runtime requirement: **Node.js 20+**.
- Rocket data is stored in an in-memory repository (`Map`), so state resets when the process restarts.
- The repository is abstracted behind `RocketRepository` so the router can be tested with a custom implementation.
- Request validation is enforced for rocket names, ranges, and capacities before any write is accepted.
- The app logs structured JSON events to stdout for monitoring and debugging.
- There is no authentication, authorization, or persistence layer.

## Technical Implementation

### Core files
- `src/index.ts` boots the server and starts listening on the configured port.
- `src/app.ts` creates the Express app, attaches middleware, registers `/health`, and wires the rockets router.
- `src/rockets.ts` implements the `/rockets` CRUD routes and validation logic.
- `src/rocket.ts` defines the rocket model and supported ranges.
- `src/rocket-repository.ts` defines the repository interface and the default in-memory implementation.
- `src/logger.ts` provides structured logging helpers for application and request events.

### Logging behavior
- Logs are emitted as single-line JSON objects to stdout.
- Each log includes a UTC `timestamp` and an `event` name.
- Request lifecycle logs capture method, route, status, elapsed time, and outcome.
- Rocket CRUD events log IDs for create/update/delete actions.
- Error handling logs unexpected or validation-related request issues without exposing request bodies.
